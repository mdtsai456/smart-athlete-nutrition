# 程式簡化與驗證

## 範圍

檢查前端頁面、API 存取、餐點流程、營養計算及 Node.js 測試。保留既有 UI 修改、範例圖片與資料相容處理。資料庫版本目錄未刪除；本次未啟動 MariaDB 或執行資料庫整合測試。

## 移除與修正

| 項目 | 原行為 | 修改後 |
| --- | --- | --- |
| 讀取餐點 | 讀取會推進分析，可能建立辨識項目 | 讀取不修改資料；模擬分析由 `finishMealAnalysis` 明確啟動 |
| 畫面輪詢 | 反覆讀取及重畫來完成模擬分析 | 一次明確執行分析，再顯示結果 |
| 項目操作 | 先查項目資料表取得餐點 ID，再送出命令 | 呼叫端傳入已知餐點 ID；正式模式只呼叫一次命令 API |
| Mock 驗證包裝 | guard 重複判斷已排除的正式模式 | 直接呼叫 session 驗證；移除不需 async 的角色轉換 |
| Mock 延遲 | 每次資料表請求固定等待 120ms | 移除人工等待；保留非同步介面 |
| 數字輸入 | 空白、null、布林值可能被轉成 0 | 拒絕非數字輸入；允許數字字串及合法的 0 |
| 測試儲存 | 只檢查 localStorage 是否存在 | 檢查 getItem 與 setItem；不可用時使用記憶體 |
| 球員操作 | 修改命令未驗證餐點所屬球員 | Mock 建立、修改、送出及模擬分析檢查所屬球員 |
| 對話框重畫 | 舊請求回來時可能套用到新的餐點草稿 | 比對草稿物件，略過過期回應 |

## 驗證

基準測試：47 項，37 項通過、10 項失敗。失敗原因為目前 Node.js 環境的 localStorage 沒有可用的 setItem。

修改後：51 項全部通過，執行約 0.54 秒。新增四項測試，驗證讀取沒有副作用、空白數值拒絕、HTTP 命令只請求一次，以及球員不能操作他人的餐點。這是修改前後的回歸比較，不代表完成所有環境的效能測試。

## 保留的設計

- API、Service、UI 分層：避免畫面依賴資料表或傳輸方式。
- 營養快照、版本檢查及重複送出識別：保留歷史攝取值並避免重複提交。
- 各角色 HTML 入口：維持現有網址與角色頁面。
- Mock、範例資料及測試：正式 API 尚未完成，仍用於本機操作與驗證。

## 正式串接前仍需完成

- 正式後端須驗證所有讀寫權限、組織範圍及項目所屬餐點。前端 Mock 檢查不能取代後端授權。
- 食物與營養資料目前分筆寫入。正式後端應使用交易，確保新增或匯入失敗時不留下部分資料。
- Mock 多表操作不是資料庫交易，也沒有跨瀏覽器分頁的鎖定。正式版須以後端交易處理版本檢查與更新。
- 攝影機影像上傳、正式辨識工作與狀態輪詢仍須由後端提供。模擬辨識在 HTTP 模式下會明確拒絕執行。

## 第二次檢查：紀錄篩選與歷史統計

本次檢查飲食紀錄篩選、首頁餐列、區間統計、每日計畫查找、餐點 API、相關測試及註解。未重寫已通過驗證的頁面結構。

### 修正

| 問題 | 修改 | 驗證 |
| --- | --- | --- |
| 所有日期使用檢視當日的營養目標 | 各日使用最新每日計畫，沒有計畫時使用該日有效的期間目標；先計算每日比例，再取平均 | 兩日目標分別為 2,000 與 3,000 kcal、攝取均達標時，平均由錯誤的 125% 改為 100% |
| 沒有歷史目標的日期仍套用目前目標 | 無目標日期不計入該營養素的平均達成率，也不算達標日 | 新增缺少目標測試 |
| 區間統計將項目已清空的餐點算作有紀錄 | 使用既有 mealHasItems，與當日統計及紀錄頁一致 | 空餐點不增加紀錄數，達成率顯示未設定 |
| 首頁只列三餐與點心 | 列出紀錄中的其他餐別，包含訓練前後 | 顯示訓練前後餐點，不增加三餐紀錄數 |
| 新增篩選缺少持續回歸驗證 | 補上營養師與教練的組合篩選測試 | 驗證指定球員、多選餐別、全部紀錄及無符合結果 |
| 狀態註解誤稱所有篩選都跨頁保存 | 說明 sessionStorage 與目前頁面狀態的差別 | 對照 state.js 的讀寫位置 |

### 刪除與合併比較

- 移除 openDraftMeal 的單層函式轉接，改為既有 createMeal 的匯出別名。名稱與呼叫方式不變。
- 移除 mutateMeal 中無法執行的 default 分支。函式入口已拒絕不支援的動作。
- 合併兩處最新每日計畫的篩選與排序，改為共用 latestDailyPlan。只取最大版本，不建立排序陣列。頁面載入、儲存版本檢查與歷史統計使用同一規則。
- 保留 API、Service、UI 分層、版本檢查及營養快照。這些設計仍負責傳輸隔離、衝突檢查與歷史資料保存。

這是刪除與修改前後的行為比較，不是效能基準測試。先加入三項錯誤重現測試，三項均在修正前失敗。修正及簡化後，加上篩選與缺少目標的測試，共 57 項全部通過。

### 尚未驗證或仍有限制

- 未執行瀏覽器視覺測試、實體攝影機測試及正式後端整合測試。
- 每日計畫已儲存絕對營養值。沒有每日計畫時，按體重設定的期間目標仍使用球員目前體重；要重建歷史目標，需要體重歷史或當日目標快照。
- 現有營養達標比例是產品規則，本次未修改，也未將它視為醫療判定。
- Node.js 仍輸出 localStorage 路徑警告。測試使用既有記憶體儲存備援，未因此失敗。
- 正式後端授權、多表交易、影像上傳與辨識工作仍需依前述項目實作。
